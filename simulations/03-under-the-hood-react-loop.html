👁️ Under The Hood: The ReAct Loop (Lesson 04)

Witness how a manual Python while loop orchestrates multi-turn sequential tool steps in intermediate memory.

ReAct Cycle 1

Solving the Multiplication Segment

The loop starts. Sridhar's agent history contains only the `HumanMessage` prompt: "What is 347 * 86, and then divide by 5?"

🧠 THINK (Thought)

"The user wants to multiply 347 by 86, and then divide that by 5. First I must calculate 347 * 86. I will use the `calculate` tool."

🎬 ACT (Action)

Call Python tool `calculate` with payload: {"expression": "347 * 86"}

👁️ OBSERVE (Observation)

The calculation function returns: "29842". We wrap it in a `ToolMessage` and loop back.

ReAct Cycle 2

Solving the Dependent Division Segment

The model receives the full memory stack: 1 User prompt, 1 AIMessage tool request, and 1 ToolMessage observation. It analyzes and makes the next selection.

🧠 THINK (Thought)

"The result of 347 * 86 is 29842. Now I must divide this number by 5. I will call the `calculate` tool again."

🎬 ACT (Action)

Call Python tool `calculate` with payload: {"expression": "29842 / 5"}

👁️ OBSERVE (Observation)

The calculation function returns: "5968.4". We wrap it in a `ToolMessage` and loop back.

ReAct Cycle 3

Formulating the Final Output

The model sees all results are complete and outputs a final conversational conclusion. The while loop detects `.tool_calls` is empty and terminates cleanly.

# Final conversational AIMessage content
"The result of multiplying 347 by 86 is 29,842. Dividing that result by 5 gives 5,968.4."

🧠 Takeaway for Developers

Without the ReAct loop, an LLM would try to answer in one single turn, leading to immediate computational errors since it has no internal calculator. ReAct solves this by interleaving multi-turn observations into the prompt window.
