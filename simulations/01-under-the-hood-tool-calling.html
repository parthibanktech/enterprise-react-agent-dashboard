🛠️ Declarative Tool Calling (Lesson 01 & 02)

Witness how an LLM transforms simple Python function signatures into formatted JSON requests without running any code.

Step 1: Python Signature Binding

Function Signatures as Prompt Instructions

When you bind a tool `@tool` in Python, LangChain parses its name, docstring, parameter types, and default values into a structured JSON Schema.

# Python Code
@tool
def calculate(expression: str) -> str:
    """Evaluate any mathematical expression precisely."""
    return str(eval(expression))
Step 2: JSON Schema Compilation

What the Model Sees

This JSON Schema is injected directly into the system prompts of ChatDeepSeek to inform it exactly when and how to structure parameters.

{
  "name": "calculate",
  "description": "Evaluate any mathematical expression precisely.",
  "parameters": {
    "type": "object",
    "properties": {
      "expression": {
        "type": "string"
      }
    },
    "required": ["expression"]
  }
}
Step 3: Declarative Selection Output

The .tool_calls Output payload

Instead of giving a text answer, the model interrupts its prediction loop and outputs a declarative parameter request. **NOTE**: No Python execution has occurred yet!

# Raw JSON response payload returned by LLM
[
  {
    "name": "calculate",
    "args": {
      "expression": "347 * 86"
    },
    "id": "call_abc123xyz789",
    "type": "tool_call"
  }
]

⚠️ Critical Takeaway for Students

Tool calling is purely declarative routing! The model only formats the JSON parameters indicating which tool it *wishes* to run. It is the role of your execution engine (Python code) to intercept this payload, run the function, and feed the observation back to the model.
